# نمونه پروژه: داشبورد مدیریت پخش و انبار (Power BI)

این پروژه یک نمونه‌کار است که ساختار مدل داده، کد Power Query و سنجه‌های DAX مورد نیاز برای دو داشبورد «فروش و پخش» و «انبار و موجودی» را نشان می‌دهد. داده‌های استفاده‌شده کاملاً نمونه و تصادفی هستند و هیچ اطلاعات واقعی مشتری در آن وجود ندارد.

## ساختار پوشه‌ها

```
data/
  Sales_1403_01_Farvardin.xlsx      داده فروش فروردین (شامل ستون Visitor)
  Sales_1403_02_Ordibehesht.xlsx    داده فروش اردیبهشت (بدون ستون Visitor)
  Sales_1403_03_Khordad.xlsx        داده فروش خرداد (شامل ستون اضافه SalesChannel)
  Inventory_1403_01_Farvardin.xlsx  داده انبار فروردین
  Inventory_1403_02_Ordibehesht.xlsx داده انبار اردیبهشت
  Inventory_1403_03_Khordad.xlsx    داده انبار خرداد
PowerQuery_M_Code.md                کد M برای تقویم شمسی و یکپارچه‌سازی فایل‌ها
DAX_Measures.md                     سنجه‌های DAX هر دو داشبورد
```

فایل‌های فروش سه ماه عمداً با ستون‌های ناهماهنگ ساخته شده‌اند تا دقیقاً همان مشکلی را که کارفرما توضیح داده شبیه‌سازی کنند: ماه اردیبهشت ستون «Visitor» را ندارد و ماه خرداد یک ستون اضافه به نام «SalesChannel» دارد. کد Power Query در فایل `PowerQuery_M_Code.md` نشان می‌دهد این ناهماهنگی چگونه قبل از یکپارچه‌سازی مدیریت می‌شود.

## ساختار مدل داده (Star Schema)

```
DimDate (تقویم شمسی)  ──┐
DimCustomer            ─┼──> FactSales (فروش)
DimProduct             ─┘

DimDate (تقویم شمسی)  ──┐
DimProduct             ─┼──> FactInventory (انبار)
DimWarehouse            ─┘
```

هر دو Fact Table به جدول‌های Dimension مشترک (تاریخ شمسی و کالا) وصل می‌شوند تا طبق درخواست کارفرما، هر دو داشبورد روی یک مدل داده واحد ساخته شوند، نه دو فایل جدا.

## مراحل ساخت در Power BI Desktop

۱. شش فایل اکسل پوشه `data` را در یک پوشه محلی قرار دهید و با `Folder.Files` طبق کد بخش ۳ فایل `PowerQuery_M_Code.md` وارد Power BI کنید (یا هرکدام را جداگانه Import کرده و Append بزنید).
۲. تابع تبدیل تاریخ شمسی (`fnToJalali`) و جدول `DimDate` را طبق بخش ۱ و ۲ همان فایل بسازید.
۳. جدول‌های Dimension کوچک (مشتری، محصول، انبار) را از داده‌های Fact با Remove Duplicates استخراج کنید یا مستقیم از داده منبع کارفرما بسازید.
۴. در Model View، رابطه‌ها را طبق نمودار بالا وصل کنید (هر Dim به Fact با کاردینالیتی یک‌به‌چند).
۵. سنجه‌های DAX فایل `DAX_Measures.md` را در یک جدول Measure مجزا (مثلاً `_Measures`) اضافه کنید.
۶. از File > Options > Report Settings گزینه Right to left را فعال و فونت فارسی (Vazirmatn یا B Nazanin) را برای بصری‌ها تنظیم کنید.
۷. فرمت ستون‌های مبلغ را روی `#,##0 " تومان"` بگذارید.

## نکته درباره Row-Level Security

بخش انتهای فایل `DAX_Measures.md` رویکرد کلی برای محدود کردن دسترسی ویزیتور به داده استان خودش را نشان می‌دهد؛ برای اجرای کامل، جدول نگاشت کاربر-به-استان لازم است که در این نمونه پیاده نشده است.
